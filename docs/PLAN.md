# 챙겨요 — 기획서

- 최종 업데이트: 2026-11-23
- 단계: 기획
- 상태 표기: `확정` / `제안` / `보류` (기준은 `AGENTS.md` 3장)

---

## 0. 용어 사전

| 용어 | 뜻 |
|---|---|
| 할 일 (task) | 사용자가 기억하고 싶은 행동. 예: 체육복 챙기기, 물 사기 |
| 장소 블록 (place block) | 사용자가 등록한 장소. 기본은 집·회사, 추가 가능 |
| 장소 종류 (place category) | 특정 지점이 아닌 종류. 예: 편의점, 마트, 약국 |
| 트리거 (trigger) | 알림이 울리는 조건. 도착 / 출발 / 근처 / 가는 길에 |
| 가는 길에 (en route) | 출발지에서 목적지로 이동하는 동안 들를 곳 근처에서 알리는 단계형 트리거 |
| 사용자 표현 캐시 (user phrase cache) | 사용자가 확인한 표현 → 해석 결과 저장소. 같은 표현은 LLM 없이 즉시 처리 |
| 확인 카드 (confirm card) | 입력 직후 해석 결과를 보여 주는 카드. 3초 뒤 자동 저장 |
| 캐릭터 (character) | 위젯·알림에서 할 일의 상황을 보여 주는 마스코트 |
| 위치 감시 (geofence) | OS가 특정 영역 진입·이탈을 감지하는 기능 |

## 1. 문제

사람들은 **특정 장소에서 해야 할 일**을 그 순간에 자주 까먹는다.

- 집에 가서 내일 준비물 챙기기
- 집에 가는 길에 슈퍼에 들러 물 사기
- 퇴근길에 물건 사 오기

기존 위치 알림 앱(기본 미리알림 등)으로도 가능하지만 실제로는 안 쓰인다.

| 실패 지점 | 설명 |
|---|---|
| 입력이 귀찮음 | 지도에서 장소 찍고, 반경 정하고, 조건 고르는 단계가 많음 |
| 앱 자체를 잊음 | 앱을 열어야 한다는 사실조차 까먹음 |
| 알림 시점이 틀림 | "집 도착"에 울리면 이미 마트를 지나친 뒤 |
| 알림이 무시됨 | 한 번 울리고 사라지면 그대로 잊힘 |

## 2. 컨셉 — `확정`

**장소 + 할 일을 한 문장으로 말하면, 알맞은 순간에 캐릭터가 알려 주는 앱.**
최우선 가치는 **사용자 편의성**이다.

---

## 3. 핵심 구조

### 3.1 장소 블록 — `확정`

- 기본 장소: **집, 회사** (자주 머무는 곳을 감지해 "여기가 집 맞아요?" 한 번만 확인 — `제안`)
- 추가 장소: 사용자가 원하는 장소를 블록으로 추가 (헬스장, 부모님 댁 등)
- 장소 종류 블록: 편의점, 마트, 약국 등 "아무 ○○" — `제안`
- 블록은 모듈처럼 가볍게 다룬다.

### 3.2 입력 방식 — `확정: 음성 중심`

- 기본 입력은 **음성 한 문장**: "집에서 체육복", "집에서 학회 영수증", "퇴근할 때 우산"
- 같은 문법을 **텍스트로도** 받는다 (조용한 장소용) — `제안`
- **드래그 블록 화면은 입력 수단이 아니라 확인·수정 화면**으로 쓴다 — `제안`
  - 잘못 들어간 장소 옮기기, 걸려 있는 할 일 한눈에 보기

### 3.3 앱을 안 열고 입력하는 경로 — `제안`

| 플랫폼 | 경로 |
|---|---|
| iOS | Siri 문구, 액션 버튼, 잠금화면·홈 위젯 |
| Android | 빠른 설정 타일, 홈 위젯, 어시스턴트 연동 |

MVP에 최소 하나는 반드시 포함한다 ("앱 존재를 잊는 문제" 대응).

## 4. 사용자 흐름

```
[말하거나 적기]  Siri / 위젯 / 액션 버튼
      ↓
[음성 → 텍스트]  OS 내장 음성 인식
      ↓
[해석]           사용자 표현 캐시 → LLM (기기 내장 → 클라우드)
                 결과: 장소 + 트리거 + 할 일 + 물건 종류
      ↓
[확인 카드]      "집 도착하면 · 체육복"  3초 뒤 자동 저장 (되돌리기만 표시)
      ↓ (장소가 애매할 때만)
[장소 블록 선택] 탭 한 번
      ↓
[위치 감시 등록] 도착 / 출발 / 장소 종류 / 가는 길에
      ↓
[알림 + 캐릭터]  완료 / 다음에
      ↓ (미완료)
[다시 알림]      다음 출발 때 등
```

## 5. 트리거

### 5.1 트리거 종류 — `제안`

| 트리거 | 예시 문장 | 동작 |
|---|---|---|
| 도착 (arrive) | 집에서 체육복 | 집에 도착해 몇 분 머물렀을 때 |
| 출발 (depart) | 퇴근할 때 우산 | 회사를 떠날 때 |
| 근처 (near_category) | 다음에 약국 가면 약 | 아무 약국 근처를 지날 때 |
| 가는 길에 (en_route) | 집에 가는 길에 물 | 단계형 (5.3) |

### 5.2 챙기는 물건의 기본 재알림 — `제안`

"집에서 체육복"처럼 **물건을 챙기는 할 일**은
1. 집 도착 시 알림
2. 완료하지 않았으면 **다음에 집을 나설 때** 한 번 더 알림 (실제 마지막 기회)

사용자가 따로 설정하지 않아도 기본값으로 동작한다.

### 5.3 "가는 길에" 단계형 트리거 — `확정`

예: "집에 가는 길에 물"

해석 결과:
- 출발지: 현재 위치 ("퇴근길에"면 회사)
- 목적지: 집
- 들를 곳: 물건에서 추론 (물 → 편의점·마트)
- 할 일: 물 사기

| 단계 | 조건 | 캐릭터 문구 |
|---|---|---|
| 1. 출발 | 현재 장소를 떠나고 집과의 거리가 줄어들기 시작 | "물 사러 가자" (이동 중 표시 시작) |
| 2. 경로 | 들를 곳(편의점) 근처를 지날 때 | "저기 편의점!" |
| 3. 마지막 기회 | 목적지 반경 약 500m 안 | "집 앞 마지막 편의점이야" |
| 4. 놓침 | 완료 안 하고 목적지 도착 | "내일 퇴근길에 다시 알려줄게?" |

구현 포인트:
- "목적지 방향 이동 중" 판단은 정확한 경로가 아니라 **목적지와의 거리가 줄어드는지**로 한다 (길찾기 API 불필요).
- 들를 곳은 **출발 감지 순간** 목적지 방향의 가까운 몇 곳만 위치 감시에 등록하고, 이동하며 교체한다 (iOS 20개 제한 대응).
- 들를 곳을 직접 말하면 ("퇴근길에 마트에서 물") 그 장소 종류를 쓴다.

## 6. 캐릭터 UI — `확정: 외부 UI에 귀여운 캐릭터로 상황 표시`

### 6.1 상태별 표시 — `제안`

| 상태 | 캐릭터 | 문구 예시 |
|---|---|---|
| 등록 직후 | 기본 표정 | "집 가면 체육복, 기억할게" |
| 이동 중 | 걷는 자세 | "같이 집에 가는 중" |
| 도착 | 놀란 표정, 팔 들기 | "체육복 챙겨!" |
| 완료 | 기쁜 표정 | "챙겼다! 내일 준비 끝" |
| 놓침 | 아쉬운 표정 | "내일 다시 알려줄게" |

### 6.2 조립식 이미지 — `제안`

입력마다 AI 이미지를 생성하지 않는다 (느림, 비용, 캐릭터 일관성 깨짐). 미리 만든 조각을 조립한다.

| 조각 | 수량 | 설명 |
|---|---|---|
| 캐릭터 표정·자세 | 상태 수만큼 (약 5~8) | 기다림, 걷기, 놀람, 기쁨, 아쉬움 |
| 장소 배경 | 장소 블록 수만큼 | 집, 회사, 마트, 편의점 등 |
| 물건 아이콘 | 30~50개 | 옷, 서류, 음료, 우산, 약 등 종류별 |
| 말풍선 문구 | 템플릿 | "{물건} 챙겨!", "같이 {장소} 가는 중" |

해석 단계에서 `item_category`(물건 종류)를 함께 뽑으면 바로 조립된다.

### 6.3 표시 위치 — `제안`

| 위치 | 용도 |
|---|---|
| 홈·잠금화면 위젯 | 등록 직후, 완료 상태. 평소에도 보여서 앱 존재를 상기시킴 |
| iOS Live Activity·다이내믹 아일랜드 / Android 상시 알림 | 이동 중 상태 |
| 푸시 알림 | 도착·출발 순간 |

제약: 위젯은 OS가 정한 시점에만 다시 그리는 정지 화면이라 연속 애니메이션이 어렵다. **상태마다 정지 컷 하나씩** 교체하는 방식으로 설계한다.

## 7. 알림 동작 — `제안`

- 완료를 누르기 전까지 사라지지 않음 (이동 중에는 Live Activity / 상시 알림)
- 알림에서 바로 선택: **완료 / 다음 ○○에서 다시 / 내일 이 시간**
- 놓친 할 일은 실패로 끝내지 않고 다음 기회로 넘긴다

## 8. 기술 구조

### 8.1 음성 → 텍스트 (무료) — `제안`

| 플랫폼 | 방식 | 비고 |
|---|---|---|
| iOS 26+ | SpeechAnalyzer (기기 내 처리, 한국어 지원) | iPhone 11 시리즈·SE 2세대 미지원 보고 있음 → 구형은 기존 받아쓰기로 대체 |
| Android | 기본 SpeechRecognizer | 무료 |
| 대안 | Whisper (오픈소스) | 앱 용량 부담으로 비추천 |

### 8.2 텍스트 → 장소·트리거 해석 — `확정: LLM 중심` / 순서 `제안`

규칙만으로는 표현 변형("교복 챙기자 / 교복 기억 / 귀가하면 교복")을 다 처리할 수 없으므로 **LLM을 기본 해석기**로 쓴다. 상세는 `PARSING_SPEC.md` 0장.

순서: **사용자 표현 캐시 → 기기 내장 LLM → (미지원 기기) 클라우드 LLM → (오프라인) 최소 규칙**

| 선택지 | 비용 | 한계 |
|---|---|---|
| 최소 규칙 (`PARSING_SPEC.md` 1장) | 무료, 즉시, 오프라인 | 정해진 표현만 처리 → 오프라인 보조용 |
| Apple Foundation Models | 무료, 기기 내 | Apple Intelligence 지원 기기만 |
| Android Gemini Nano (ML Kit Prompt API) | 무료, 기기 내 | 지원 기기 제한적 (Pixel 9·10, 일부 플래그십) |
| Gemini API 무료 등급 | 무료 | 개발·테스트용. 사용량 제한 낮음, 무료 등급 데이터는 제품 개선에 사용됨 → 서비스 출시 시 유료 Flash-Lite급으로 전환 |

MVP는 **Gemini 무료 등급(개발용) + 사용자 표현 캐시**로 시작한다.

### 8.3 위치 감지 제약 — `제안`

| 항목 | 내용 | 대응 |
|---|---|---|
| iOS 지역 감시 개수 | 앱당 20개 | 장소 종류는 현재 위치 근처만 동적으로 교체 등록 |
| 위치 "항상 허용" 권한 | 이탈이 가장 많은 지점 | 첫 실행이 아닌 **첫 할 일 등록 순간**에 이유와 함께 요청 |
| 배터리 | GPS 상시 사용 금지 | OS 지역 감시 + 이동 감지(걷기·운전) 조합 |

### 8.4 개발 스택 — `제안`

- Unity는 백그라운드 위치 처리에 부적합
- 네이티브(Swift / Kotlin) 또는 Flutter·React Native + 네이티브 모듈

## 9. MVP 범위 — `제안`

1. 집·회사 자동 감지 + 원탭 확인, 장소 블록 추가
2. 한 줄 입력(음성·텍스트) → 장소·트리거·할 일 해석
3. 트리거: 도착, 출발, 장소 종류 근처, 가는 길에
4. 확인 카드 (3초 자동 저장) + 애매할 때 블록 선택
5. 완료할 때까지 남는 알림 + "다음에" 버튼 + 챙기는 물건 재알림
6. 앱 밖 입력 경로 최소 1개 (Siri/위젯/액션 버튼 중)
7. 캐릭터 위젯 (상태별 정지 컷)

### 검증 아이디어 — `제안`

앱 개발 전 iOS 단축어 자동화로 2주간 직접 사용해 보고, 실제로 쓰는 트리거와 무시되는 알림을 기록한다.
