# 실험: 앱 내장 소형 해석 모델 가능성

- 최종 업데이트: 2026-11-23
- 코드: `poc/small-nlu/`
- 상태: 실험 결과 (채택 여부는 `OPEN_QUESTIONS.md` #10)

## 1. 질문

"집에 가면 체육복", "교복 챙기자 집에서", "퇴근길에 마트에서 물" 같은 문장을
**앱에 넣을 수 있는 작은 모델**이 장소·트리거·할 일로 해석할 수 있는가?

## 2. 실험 조건

| 항목 | 내용 |
|---|---|
| 모델 | 글자 단위 BiGRU 2층 + 헤드 4개(trigger, anchor, origin, action) + 글자 태그(ITEM, PLACE, STOP) |
| 파라미터 | 약 157만 개 |
| 사전학습 | **없음** (실험 환경에서 HuggingFace 차단 → 처음부터 학습). 실제 개발에서는 한국어 사전학습 소형 인코더를 쓰면 더 좋아질 여지가 큼 |
| 학습 데이터 | `gen_data.py`로 합성 4만 문장 (장소 표현 × 물건 × 끝말 × 어순 × 띄어쓰기 생략 × 가짜 명사) |
| 테스트 | `test_set.py`: 사람이 직접 쓴 118문장. 새 표현 20, 학습에 없는 물건 83 |
| 학습 시간 | CPU 2코어, 약 6분 |

## 3. 결과 (테스트 118문장, 모델 v1)

| 항목 | 정확도 |
|---|---|
| 트리거 (도착/출발/가는 길에) | 98.3% |
| 기준 장소 (집/회사/기타) | 99.2% |
| 출발지 (가는 길에) | 100% |
| 장소 이름 (헬스장, 마트 등) | 99.2% |
| 들를 곳 (편의점 등) | 100% |
| **물건 이름** | **85.6%** |
| 행동 (챙기기/사기/보내기) | 82.2% |
| 전체 프레임 (행동 제외 전부 정답) | 84.7% |

| 배포 지표 | 값 |
|---|---|
| 모델 크기 | fp32 6.3MB / int8 약 1.6MB (임베딩까지 양자화 가정) |
| 속도 | CPU 1스레드 문장당 약 1.6ms |
| int8 정확도 | fp32와 동일 |

### 신뢰도 기준으로 클라우드 LLM에 넘기면

| 기준 | 기기에서 처리 | 기기 처리분 정확도 | 클라우드로 |
|---|---|---|---|
| 0.7 | 81% | 91.6% | 19% |
| 0.9 | 66% | 92.3% | 34% |

## 4. 해석

- **구조 파악(언제·어디서)은 소형 모델로 충분하다.** 처음 보는 끝말("챙깁시다", "기억")과 어순 변화도 거의 다 맞췄다.
- **약점은 물건 이름의 경계**다. 오류 대부분이 이 유형:
  - 처음 보는 동사를 물건에 포함: "마우스 바꾸기" → `마우스 바꾸`, "청첩장 돌리기" → `청첩장 돌리`
  - 처음 보는 시간 표현을 물건으로 착각: "귀가 후 롱패딩" → `후 롱패딩`, "퇴근 직전 노트북 거치대" → `전 노트북 거치대`
  - 띄어 쓴 긴 물건을 자름: "떡볶이 떡" → `떡볶이`
- 생성기를 일반적으로 보강한 v2(복합 명사·시간 접두어 추가)는 오히려 물건 81.4%로 낮아졌다 → 합성 데이터 튜닝만으로는 한계, **동사·시간 표현 다양성**과 **사전학습 인코더**가 핵심.
- "화분 물 주기"처럼 물건이 아니라 **행동** 자체가 할 일인 경우는 현재 라벨 체계(`item`)로 표현이 어렵다 → 스키마에 `do`(행동형 할 일) 처리 필요.

## 5. 결론 (제안)

1. 소형 모델 내장은 **가능성 있음**. 크기(수 MB)와 속도(수 ms)는 문제가 아니다.
2. 권장 구조: **내장 소형 모델 → 신뢰도 낮으면 클라우드 LLM → 확인 카드**. 현재 수준에서도 약 80%를 기기에서 처리 가능.
3. 물건 이름 정확도는 확인 카드가 보완한다 (틀려도 사용자가 한 번 탭으로 수정 → 사용자 표현 캐시·재학습 데이터).
4. 다음 실험 후보:
   - 한국어 사전학습 소형 인코더(KoELECTRA-small급) 미세조정으로 물건 경계 비교
   - 큰 LLM으로 동사·시간 표현이 다양한 학습 문장 대량 합성 (현재는 템플릿 기반)
   - `do` 행동형 할 일 라벨 추가
